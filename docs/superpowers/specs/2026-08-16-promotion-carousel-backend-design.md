# Promotion Carousel + Backend Design

## Goal

Replace the static client-side left hero panel with an accessible, data-driven promotion carousel that renders at most three real images, while adding a safe PostgreSQL-backed backend boundary for future admin upload and replacement.

## Evidence and boundary

- The current client page has a static `hero-copy` panel beside the CV upload form.
- The current frontend has no promotional image assets and no promotion endpoint.
- The current backend already owns Gin routing, pgx/PostgreSQL access, explicit CORS, rate limits, generic public errors, and local-only binding.
- The product requires no mock data. Therefore the initial database contains zero promotion rows and the UI keeps the existing verified product copy as a no-data fallback.
- The attached screenshot is a visual reference for the existing composition, not a promotion asset or runtime data source.

## Approved approach

Use a data-driven carousel component with an additive API contract. The client asks for active promotion metadata, caps the response at three records, and loads each image from a dedicated image route. The backend stores the current image bytes and metadata in PostgreSQL, keyed by slot `1..3`, so replacing a slot changes the client content without a frontend rebuild or a separate storage service.

The admin write boundary is separated from the client read boundary. It is implemented as a future-admin-ready API, but it is disabled unless a server-side `PROMOTION_ADMIN_TOKEN` is configured. The current API remains loopback-only until the product's real admin authentication/session contract exists. No browser client receives the admin token.

## Architecture

### Public client read path

```text
SvelteKit client
  -> GET /api/v1/client/promotions
  <- active metadata, ordered by slot, max 3

Carousel slide
  -> GET /api/v1/client/promotions/{slot}/image?v={content_hash}
  <- validated image bytes with Content-Type, ETag, and cache headers
```

If the endpoint returns an empty list, an invalid payload, or a temporary dependency error, the client keeps the existing product hero copy. It does not create a fake slide, placeholder image, or fabricated promotion record.

### Future admin write path

```text
Admin UI (future)
  -> PUT /api/v1/admin/promotions/{slot}
  <- the stored slot metadata

Admin UI (future)
  -> DELETE /api/v1/admin/promotions/{slot}
  <- 204 and the slot is absent from the client read list
```

The slot is the idempotency boundary: repeating a `PUT` for the same slot replaces that slot rather than creating duplicate active records. The database unique constraint enforces the maximum of three slots independently of the caller.

## PostgreSQL data contract

Add migration `000002_promotion_slides.up.sql` and its reversible down migration. The `public.promotion_slides` table owns:

- `id uuid` generated by PostgreSQL.
- `slot smallint` constrained to `1`, `2`, or `3`, unique.
- `image_bytes bytea` containing only the validated uploaded image.
- `mime_type text` constrained to `image/png`, `image/jpeg`, or `image/webp`.
- `content_hash text` containing the lowercase SHA-256 hash of the stored bytes.
- `alt_text text` required and bounded for accessible rendering.
- Optional bounded `eyebrow`, `title`, and `body` copy for overlay content.
- Optional `target_url` restricted to `http` or `https` without embedded credentials.
- `is_active boolean`, defaulting to true.
- `created_at` and `updated_at` timestamps.

The public query selects active rows only, orders by `slot ASC`, and applies `LIMIT 3`. It returns metadata but never embeds `image_bytes` in JSON. The image query selects bytes by slot and active state. `content_hash` is used for ETag and cache-busting; no source payload or unrelated user data is stored.

## HTTP contracts

### `GET /api/v1/client/promotions`

Response `200` when there are zero or more active slots:

```json
{
  "promotions": [
    {
      "id": "uuid",
      "slot": 1,
      "image_url": "/api/v1/client/promotions/1/image?v=sha256",
      "alt": "Promotion image description",
      "eyebrow": "Optional label",
      "title": "Optional promotion title",
      "body": "Optional supporting copy",
      "target_url": "https://example.com/campaign",
      "content_hash": "64-lowercase-hex-characters"
    }
  ]
}
```

The response is additive and has no effect on existing scan endpoints. `image_url`, `target_url`, and all text values are validated again by the frontend parser before rendering.

### `GET /api/v1/client/promotions/{slot}/image`

- Accepts only slots `1..3`.
- Returns the active image bytes with the stored safe MIME type.
- Returns `ETag` based on `content_hash` and `304` for a matching `If-None-Match`.
- Returns `404` for an absent or inactive slot.
- Does not return database errors, filesystem paths, or raw internal errors.

### `PUT /api/v1/admin/promotions/{slot}`

The transitional local admin boundary requires `Authorization: Bearer <PROMOTION_ADMIN_TOKEN>`. If the token is not configured, the route returns a generic `503` with `promotion_admin_disabled`. A future authenticated admin session can replace this middleware without changing the storage or client read contracts.

The multipart request contains:

- Required `image` file.
- Required `alt` text.
- Optional `eyebrow`, `title`, `body`, and `target_url` fields.

Validation rules:

- Body and copied image bytes are bounded by `MAX_PROMOTION_IMAGE_BYTES`, default `5 MiB`.
- Only PNG, JPEG, and WebP signatures are accepted; SVG and unknown formats are rejected.
- Client filename and MIME header are never trusted as the file type or storage path.
- Text fields have explicit maximum lengths.
- `target_url` must be an absolute `http` or `https` URL without username or password components.
- The endpoint upserts exactly one slot in a PostgreSQL transaction.

Response `200` returns the same metadata shape as one item in the client list. It never returns `image_bytes` or the admin token.

### `DELETE /api/v1/admin/promotions/{slot}`

The same admin authorization is required. Deleting a slot is idempotent: an absent slot still returns `204`. The public client list omits the slot on the next read.

## Frontend behavior

Create `PromotionCarousel.svelte` with a typed `PromotionSlide` input and no embedded promotion records.

- The route loads promotions after mount through `getPromotions()`.
- The API parser rejects malformed response shapes, unsafe URLs, missing alt text, non-finite values, and more than three items.
- A failed optional promotion request preserves the existing hero copy and does not block CV upload.
- With two or three real slides, autoplay advances every five seconds, pauses on hover/focus, and exposes previous/next buttons and dot buttons.
- Arrow-key navigation is supported while the carousel is focused.
- `aria-roledescription="carousel"`, slide labels, button labels, and visible focus styles are required.
- `prefers-reduced-motion: reduce` disables automatic rotation and transition animation.
- The right-hand CV form and all scan states remain unchanged.
- At mobile widths the carousel remains above the form in the existing single-column order; image content uses a bounded aspect ratio and never pushes the form outside the viewport.

The component accepts the existing hero content as a no-data fallback. That fallback is product copy already present in the repository, not mock promotion data.

## Security and operational behavior

- Client reads are public content and are limited to three records plus bounded image responses.
- Admin writes are token-gated, loopback-constrained by current configuration, rate-limited, and logged with slot/result only; tokens, image bytes, and request bodies are never logged.
- Admin actions log a safe structured event containing action, slot, result, and a request correlation ID when available.
- PostgreSQL calls use placeholders only.
- Stored text is rendered through Svelte's normal escaping; no raw HTML field is introduced.
- Image responses set a safe content type from validated stored metadata and do not support SVG.
- The transitional token is a safety bridge, not the final authentication design. Public deployment remains blocked until the admin authentication and ownership contract is implemented.

## Compatibility and non-goals

- Existing scan endpoints and frontend scan types remain unchanged.
- The endpoint family is additive under `/api/v1/client/promotions` and `/api/v1/admin/promotions`.
- No admin frontend is implemented in this slice.
- No crawler, DeepSeek, job matcher, job cache, or source approval behavior is changed.
- No promotion images are seeded or checked into the repository.
- Production object storage and final admin authentication remain explicit unknowns.

## Verification required

- Migration contract checks verify the table, slot limit, MIME allowlist, hash shape, URL constraint, and down migration.
- Go tests cover image signature/size validation, hash stability, safe URL validation, slot upsert/delete behavior, client list cap, image ETag behavior, disabled/missing/wrong admin token, generic errors, and no raw image bytes in JSON.
- Frontend tests cover response parsing, three-item cap, invalid payload rejection, fallback behavior, carousel navigation, autoplay pause, keyboard controls, and reduced-motion behavior.
- Run `gofmt`, `go test -mod=readonly ./...`, `go vet -mod=readonly ./...`, schema validation, frontend unit tests, `svelte-check`, and frontend build.
- Run desktop and mobile browser screenshots to verify wide/narrow layout, focus state, empty state, one-slide state, and three-slide state using test-only fixtures; no fixture becomes runtime data.
- Run focused security review and mandatory code-reviewer, security-auditor, and test-engineer gates before completion.

## Unknowns

- The final admin authentication/session contract is not yet defined.
- A production object-storage decision is not yet defined; PostgreSQL `bytea` is the bounded local implementation for at most three images.
- No live PostgreSQL service is currently confirmed in the environment, so runtime migration/API smoke proof may remain unavailable until the server is running.
